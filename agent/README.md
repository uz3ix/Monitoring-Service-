# Агент мониторинга

Самостоятельная программа Python 3.12+, которая собирает показатели компьютера
и отправляет их в API. Для мониторинга Windows запускайте её непосредственно
в Windows. Агенту не нужен доступ к PostgreSQL.

## Запуск на этом ПК

Из корня репозитория установите зависимости в существующее окружение:

```powershell
.\.venv\Scripts\python.exe -m pip install -r agent/requirements.txt
```

Настройки агента находятся в корневом `.env`:

```dotenv
SERVER_URL=http://127.0.0.1:8000
AGENT_ID=my-pc
AGENT_TOKEN=тот-же-токен-что-у-бэкенда
AGENT_INTERVAL_SECONDS=60
AGENT_TIMEOUT_SECONDS=5
DISK_PATH=C:/
```

Сохраните существующий `AGENT_TOKEN`; показанное значение — только пояснение.
Токен должен состоять из печатных ASCII-символов без пробелов.
Запустите базу и бэкенд по корневому README, затем в другом терминале:

```powershell
.\.venv\Scripts\python.exe -m agent --once
```

Это собирает одно измерение и отправляет его. Код выхода: 0 — HTTP 201,
1 — ошибка сбора или отправки, 2 — ошибка настроек.
Для непрерывной работы:

```powershell
.\.venv\Scripts\python.exe -m agent
```

Остановка — Ctrl+C. Текущий сбор или HTTP-запрос сначала завершится;
запрос ограничен таймаутами. Фоновый сервис Windows пока не устанавливается.
После изменения `.env` перезапустите агента.

Откройте `/docs` бэкенда, авторизуйтесь токеном и выполните
`GET /api/v1/agents/my-pc/metrics/latest`: данные будут обновляться.

## Что читать в коде

1. `__main__.py` — запуск, цикл, остановка и режим `--once`.
2. `config.py` — загрузка и проверка настроек.
3. `collector.py` — сбор показателей через psutil и время UTC.
4. `sender.py` — HTTP-запрос и обработка ответа.

CPU измеряется за одну секунду. Память берётся из `virtual_memory().used`,
диск — из `disk_usage(DISK_PATH).used`; объёмы передаются в байтах.
Определение занятой памяти зависит от ОС, поэтому значение может отличаться
от показателя в диспетчере задач. Наблюдается файловая система, содержащая
указанный путь, а не сумма всех дисков.

Первое измерение отправляется сразу после запуска и секундного замера CPU,
последующие — раз в 60 секунд по умолчанию. CPU при этом отражает секундный
замер, а не среднее за всю минуту.
Интервал отсчитывается между началами циклов, с учётом времени сбора и отправки.
Если цикл длится дольше интервала, перед следующим будет пауза не меньше секунды.
Таймаут ограничивает ожидание на этапах сетевого запроса, а не общую длительность цикла.

## Если сервер недоступен

Агент пишет ошибку в консоль и продолжает со следующего цикла. Очередь на диске
пока не реализована: следующее измерение будет новым, неотправленные данные
не восстанавливаются. При потере ответа сервер мог успеть сохранить измерение;
агент не повторяет тот же POST, чтобы не создавать дубликаты.
Для HTTP 401/403 проверьте токен, для 422 — формат данных. Тела ответов и токен
не пишутся в журнал. Редиректы отключены; системные HTTP-прокси не используются.

## Запуск на другом компьютере

Достаточно скопировать папку `agent`, установить Python и зависимости из
`agent/requirements.txt`. В родительской папке создайте виртуальное окружение,
а в `agent/.env` скопируйте `agent/.env.example` и укажите собственные настройки:

- `SERVER_URL` — адрес компьютера с бэкендом, например `http://192.168.1.10:8000`.
- `AGENT_ID` — уникальное имя этого компьютера, например `office-pc-2`.
- `AGENT_TOKEN` — токен бэкенда; доступ к настройкам базы агенту не нужен.
- `DISK_PATH` — `C:/` для Windows или `/` для Linux.

Из родительской папки запускайте `python -m agent --env-file agent/.env`.
Переменные окружения приоритетнее выбранного файла.
Для связи по локальной сети бэкенд должен слушать `--host 0.0.0.0`, а входящий
порт 8000 должен быть доступен через брандмауэр. Для внешней сети используйте HTTPS.

## Проверки

После установки `backend/requirements-dev.txt` и `agent/requirements.txt`:

```powershell
.\.venv\Scripts\python.exe -m pytest agent/tests -q -p no:cacheprovider
```

Эти тесты проверяют настройки, контракт API, сбои связи и восстановление;
запущенная база для них не нужна.
